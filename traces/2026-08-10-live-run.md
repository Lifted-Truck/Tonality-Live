# live-run — first real run inside Ableton; activation logging added

- **Queue item:** unqueued: the standing "no end-to-end test inside a live
  Ableton" gap named in Q-003's trace (traces/2026-08-09-q003-conform.md).
  Human asked to run it in Live.
- **Why:** everything through 2026-08-09 was verified over HTTP and by unit
  test; the dialogs' `close_and_send` path, the context-menu registration and
  the undo-step behaviour had only ever been exercised by construction.
- **How it was loaded:** installed the shipping artifact rather than using
  Developer Mode. `npm run package` → `extension/tonality-0.1.0.ablx`, unzipped
  to `~/Library/Application Support/Ableton/Extensions/julian-smith.tonality/`
  (needs an unsandboxed write, else it lands in an overlay Live cannot see),
  then restart Live. Chosen over `npm start` because Developer Mode makes Live
  stop hosting all ~41 installed extensions while it is on — see LIBRARY L0004.
- **Verified in Live (Live 12.4.5b10, engine mts 0.1.0, bridge on :8765):**
  1. All four actions registered and reachable — under the clip context menu's
     nested **Extensions** submenu.
  2. **Fit to Key** on a chromatic 7-note clip (C C♯ D F♯ G♯ A♯ B) → C major:
     dialog reported "Conformed 4 of 7 notes to C major. 4 sat exactly between
     two scale notes and were resolved 'previous'." Matched the bridge's
     prediction exactly (`[60,60,62,65,67,69,71]`, 4 snapped, 4 ties, 0
     collisions). Piano roll confirmed.
  3. **One undo step** — a single Cmd+Z reverted all four pitch changes at once;
     Undo History gained exactly one entry. Q-003 criterion 3, behaviourally.
  4. **Conform to Scale** — picker listed the engine's full 37-scale catalog
     (served via `GET /scales`), and the degree preview updated live
     (`Minor Pentatonic` on C → `C D# F G A#`). Applied → "Conformed 5 of 7
     notes to C Minor Pentatonic. 2 ... resolved 'previous'." Matched the bridge
     (`[60,60,63,65,67,70,70]`).
  5. **Collision dedupe** — stacked C+C♯ at one onset plus a G; snap merged
     C♯ onto C, and the result was "…1 note landed on a pitch already in use and
     was merged away." Clip went 3 notes → 2. Ruling R2 honoured end-to-end.
- **Correction worth recording:** my hand-computed expectation for Minor
  Pentatonic said 1 tie; the engine said 2 and was right — B is equidistant from
  A♯ and C because pitch-class distance wraps. The engine's arithmetic beat mine;
  no code change needed.
- **What changed in the repo:** `extension/src/extension.ts` now logs on
  activation and after registering its actions. This is a fix for a real
  diagnostic trap: `ExtensionHost.txt` contains only what each extension chooses
  to log, so our silence was misread as a failed load and cost a chunk of this
  session (LIBRARY L0005). Also LIBRARY L0004/L0005 + INDEX pointers, and the
  ROADMAP oracle note now distinguishes "no automated in-Live test" from
  "unverified in Live".
- **Alternatives rejected:** Developer Mode + `npm start` (would disable all the
  user's installed extensions while on); hand-drawing the test clip in the GUI
  (used able-mcp's LOM bridge to set exact pitches instead, so the input was
  known precisely).
- **Verify:** `./verify fast` exit 0 after the logging change; the installed
  bundle's sha256 matches the repo's `dist/extension.js`; Live's host log shows
  `[tonality] activating (SDK 1.0.0)` and `[tonality] ready — 4 MidiClip actions
  registered` at 2026-08-10T12:29:58.
- **Open questions:** an automated in-Live test remains out of scope (no
  harness). The test clip lived in an unsaved Untitled set and was discarded.
  Windows/other-Live-version behaviour untested.
