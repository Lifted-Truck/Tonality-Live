# q007-remap — `remap_by_degree` on /transform; modal_transform deferred

- **Queue item:** Q-007. Cites traces/2026-08-11-conform-vs-remap.md (the
  adoption) and traces/2026-08-09-q003-conform.md (the conform wiring it parallels).
- **Why:** `/transform` exposed only conform, a *proximity* map. Every "change the
  mode" request therefore routed into a lossy snap that destroys scale walks —
  the failure the human hit in Live. `remap_by_degree` is the translation
  operation; without it the workshop (Q-004) would be wrong by construction.
- **Human gate:** granted in session ("Let's see it") for the `/transform`
  contract addition — a §Domain protected path.
- **Evidence consulted (source, not summaries — L0006/L0007):**
  - `mts/generate/remap.py:252` — `remap_by_degree(sequence: Sequence, source_scale,
    source_root, target_scale, target_root, *, session=None) -> RemapResult`. Takes
    a **Sequence**, exactly like conform, so the anticipated adapter was
    unnecessary and `_sequence_from_payload` is reused unchanged. (The *MCP*
    wrapper takes `events: list[list]`; the generate layer is the better fit.)
  - `RemapResult` fields: `map`, `events`, `edits`, `absorbed_alterations`,
    `notes_total/diatonic/chromatic`, `tied_attachments` — same flat
    `events`+`edits` shape as `ConformResult`, so the bridge's existing
    pop-events-into-notes glue applies verbatim. Its docstring now cites
    `tonality-live-002`, confirming the provider landed our order-contract fix.
  - `mts/generate/modal.py:164` — `TransformApplication` has `events` but **no
    `edits`**; pairing lives in `TransformPlan.decisions`, and there is a
    `chromatic` policy (`rhetoric`/`strict`) that raises on unresolved holds.
- **What changed:**
  - `bridge/server.py`: op `remap_by_degree` (validates its four params, calls the
    generate layer, lets the engine's unequal-cardinality `ValueError` through to a
    400 carrying the engine's own reason); op `modal_transform` raises
    `NotImplementedError` → 501 with the reason above.
  - `bridge/test_bridge.py`: +8 tests (class `RemapByDegree`) — walk survives
    remap, **conform merges the same walk** (the contrast pinned so a semantics
    change breaks the build, not the user's clip), identity remap is a no-op,
    NoteDescription shape, edits pair on `(onset, from_midi)`, the refusal names
    the cardinalities, each missing param rejected, modal_transform visibly 501s.
    27 bridge tests total.
  - `verify`: live remap walk-preservation check (asserts 5 **distinct** pitches)
    and an explicit `400` assertion for the 7→5 refusal.
  - Docs: bridge/README gains the intent table, the walk example, and the refusal
    rationale; CLAUDE.md §Domain gains the conform-vs-remap invariant, the four
    current menu items (was stale at two), and refreshed verify targets.
- **A test I got wrong, and what it taught:** the identity-remap test first
  asserted a pitch-sorted list and failed — output is in the engine's canonical
  `(onset, midi)` order, and this walk has ascending onsets with *descending*
  pitches. L0006 bit me inside my own test for L0007. Rewritten to compare
  `{onset: pitch}` maps, which is order-agnostic and models the documented idiom.
- **Alternatives rejected:** wire `modal_transform` too (would introduce a second,
  inconsistent diff shape into the workshop before its policy UI exists — deferred
  loudly instead); catch the cardinality `ValueError` and fall back to conform
  (that is exactly the silent substitution the provider's notice warns against);
  call the MCP wrapper and adapt events↔Sequence (unnecessary once the generate
  signature was read).
- **Verify:** `./verify full` exit 0 against a live bridge, git 480490c —
  27 bridge tests OK; `/transform remap -> [67, 65, 63, 62, 60], 5 distinct
  (walk intact)`; `/transform remap 7->5 -> 400 (refused, as designed)`.
- **Open questions:** `modal_transform` still unwired (needs plan.decisions
  pairing + a chromatic-policy UI). Unequal-cardinality span policy is the
  provider's gap 31(b)/(c). No extension-side UI for remap yet — deliberately
  waiting for the workshop rather than adding a fifth menu item.
